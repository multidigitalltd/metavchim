# 06 · UX ונגישות

## 1. עקרונות UX

1. **"מה דורש טיפול היום?"** — המערכת פותחת תמיד בתשובה, לא בשאלה. הדשבורד = רשימת 5 הפעולות החשובות של היום, לא אוסף גרפים.
2. **Next Best Action בכל מקום** — כל כרטיס (ליד/נכס/קונה/התאמה) מסתיים בכפתור פעולה אחד ברור + חלופות משניות.
3. **מינימום הקלדה** — קול, בחירת צ'יפים, ברירות מחדל חכמות. טופס מלא הוא המוצא האחרון.
4. **מהירות נתפסת** — Optimistic UI, Skeletons, מעברים מיידיים; עבודות רקע עם עדכון חי (WebSocket) במקום המתנה.
5. **Mobile-First אמיתי** — המתווך בשטח. כל זרימה מרכזית חייבת לעבוד מצוין במסך 375px ביד אחת; PWA מותקנת עם התראות Push.
6. **וואטסאפ כממשק שווה-ערך** — כל מה שמופיע כהתראה ניתן לפעולה מתוך ההודעה (אישור/דחייה/עריכה בקישור קצר).
7. **אמון דרך שקיפות** — כל תוצר AI (התאמה, סיכום, תיאור) מסומן, מוסבר, וניתן לעריכה בלחיצה.

## 2. מסכים עיקריים

### זרימת "קביעת סיור" — משני הכיוונים

הסיור נקבע גם מכרטיס הנכס ("עם מי?") וגם מכרטיס הקונה או הליד
("איזה נכס?"). עד כה הכפתור היה קיים רק בצד הנכס, והצד השני נשאר
ריק לנצח — כלומר סיור בלי לדעת את מי מזמינים.

1. הכפתור בכרטיס (נכס / קונה / ליד) פותח את טופס הפגישה עם הצד
   שממנו יצאו כבר מקושר ומוצג בשמו.
2. הצד השני נבחר בטופס עצמו, בחיפוש חי מול `/search` — נכסים לפי
   כתובת, לקוחות לפי שם, טלפון וערי חיפוש, בכפוף לאותם כללי בעלות
   כמו בכל מסך. לפני שמקלידים מוצגים האחרונים, ונאמר שאלה האחרונים.
3. גם הצד שהגיע מהכתובת ניתן להחלפה — מי שלחץ בכרטיס הלא נכון לא
   צריך לחזור אחורה.
4. אין כזה במערכת? "נכס חדש" / "ליד חדש" פותחים את **טופס הקליטה
   האמיתי** ומחזירים לטופס הפגישה עם הכרטיס החדש מקושר. המזהים
   נוסעים בכתובת (מול רשימת היתר ב-`safeReturnPath`), והטיוטה
   שנכתבה עד כה נשמרת ב-`sessionStorage` וחוזרת לשדות. הטיוטה
   נצרכת **רק** בחזרה מפורשת (`draft=1` בנתיב), והקריאה מוחקת
   בכל מקרה — יציאה שננטשה לא משאירה הערות על לקוח אחד שיצוצו
   בפגישה של אחר.
5. הפגישה נרשמת בציר הזמן של **כל** כרטיס שקושר אליה — הליד וגם
   הקונה. עד כה נכתבה שורה רק לליד, כלומר סיור שנקבע לקונה לא הופיע
   אצלו בכלל.
6. אחרי השמירה, כשיש לקוח מקושר: הודעת עדכון מנוסחת בוואטסאפ —
   עם המועד בשעון ישראל ועם הכתובת, אם נבחר נכס. השליחה תמיד ביד
   של בן אדם.

### זרימת "קליטת נכס בקול" (הרגע החשוב במוצר)
1. כפתור צף "➕ נכס בקול" זמין מכל מסך (ומוואטסאפ).
2. הקלטה → מסך "מעבד..." עם שלבים חיים (תמלול ✓ → חילוץ ✓ → יצירה ✓) — לא ספינר אילם.
3. תוצאה: כרטיס נכס עם שדות מלאים מודגשים ירוק, חסרים מודגשים כתום + צ'יפים להשלמה מהירה ("יש מעלית? כן/לא").
4. מיד אחרי: "נמצאו 17 קונים מתאימים — לצפייה ושליחה".
   יעד: מהקלטה ועד הצעה מוכנה — **פחות מדקה**.

## 3. שפה ולוקליזציה

- עברית RTL כברירת מחדל, מבנה i18n מלא מהיום הראשון (אנגלית/ערבית/רוסית עתידיות).
- `dir` ו-`lang` ברמת המסמך והרכיב; אייקונים כיווניים מתהפכים; מספרים וטלפונים LTR בתוך טקסט RTL (`dir="ltr"` נקודתי).
- תאריכים, מטבע (₪) ופורמט טלפון ישראלי בכל התצוגות.

## 4. נגישות — ת"י 5568 + WCAG 2.2 AA

הנגישות מובנית מהיום הראשון, לא תוספת. יעד: Lighthouse Accessibility ≥ 95 בכל מסך.

### מחייב בכל רכיב
- HTML סמנטי (header/nav/main/button/form); ARIA רק כשסמנטיקה לא מספיקה.
- ניווט מקלדת מלא: Focus נראה, סדר Tab הגיוני, Skip-to-content, אפס מלכודות מקלדת.
- ניגודיות: 4.5:1 טקסט רגיל, 3:1 טקסט גדול — נאכף בטוקני העיצוב (ה-Design System לא מכיל צירוף שנכשל).
- כל שדה עם `<label>` אמיתי (Placeholder אינו תחליף); שגיאות ולידציה מקושרות תוכניתית (`aria-describedby`) ומוכרזות.
- כל תמונה עם alt משמעותי; דקורטיבי — `aria-hidden`.
- מודאלים: Focus Trap, סגירת ESC, החזרת פוקוס לאלמנט המקור.
- עדכונים דינמיים (התראה חיה, סטטוס עיבוד) — `aria-live` מתאים.
- טפסים קריטיים (תשלום, מחיקה): שלב אישור + אפשרות ביטול (Error Prevention).
- `prefers-reduced-motion` מכובד; ללא הבהובים.
- טקסט סקלאבילי עד 200% בלי שבירת פריסה.
- תמלול זמין לכל הקלטת שיחה (הנגשת אודיו — ממילא פיצ'ר ליבה).

### רכיבי עזר
- סרגל נגישות: הגדלת טקסט, ניגודיות גבוהה, גווני אפור, הדגשת קישורים/כותרות, עצירת אנימציות, פונט קריא — נשמר ב-localStorage.
- עמוד הצהרת נגישות כנדרש בתקנות הישראליות.
- תאימות נבדקת עם NVDA + VoiceOver + TalkBack (דפי ההצעה ללקוחות קצה — בעדיפות עליונה, הם פונים לציבור הרחב).

### אכיפה בתהליך
- axe-core אוטומטי ב-CI על כל מסך; PR שנכשל — נחסם.
- בדיקת מקלדת ידנית כחלק מ-Definition of Done של כל מסך חדש.

## 5. Design System

- ספריית רכיבים פנימית אחת (מבוססת Headless — Radix UI — עם עיצוב שלנו): Button, Card, Modal, Toast, Table, Chips, Timeline, VoiceRecorder, MatchScore, StatusBadge...
- טוקנים: צבעים (כולל מצב כהה), טיפוגרפיה, ריווח, צללים — מוכנים ל-White-Label (החלפת טוקנים פר-דייר ב-Enterprise).
- כל רכיב נולד נגיש; רכיב שלא עומד בבדיקות נגישות לא נכנס לספרייה.
- Storybook לתיעוד חי + בדיקות ויזואליות.

## 6. דפי הצעה ללקוח קצה

הדף שהקונה פותח מהוואטסאפ — כרטיס הביקור של המתווך:
- נטען < 1.5 שניות בסלולר (סטטי-ברובו, תמונות WebP/AVIF רספונסיביות, Lazy Load).
- ללא התחברות; טוקן חד-ערכי בקישור; פג-תוקף ניתן להגדרה.
- פעולות: גלריה, פרטים, "מעוניין ✓", "לא רלוונטי ✗", "בקש שיחה" — כפתור אחד לכל החלטה.
- כל אינטראקציה נרשמת → מזינה את ההתראות ("פתח 3 פעמים") ואת ניקוד הבשלות.
- נגישות מלאה — קהל רחב, מכשירים מגוונים.
