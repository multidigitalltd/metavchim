# 08 · תפעול ותחזוקה

## 1. סביבות

| סביבה | מטרה | דאטה |
|-------|------|------|
| Local | פיתוח (Docker Compose: PG, Redis, Mailpit, MinIO, Fake Providers) | סינתטי (Seeders) |
| Staging | בדיקות אינטגרציה, ספקי Sandbox (WhatsApp Test, טלפוניה) | סינתטי — **לעולם לא דאטה אמיתי** |
| Production | לקוחות | אמיתי, מוצפן |

- אחסון: ענן עם ריג'ן אירופי קרוב (זמן תגובה לישראל) או ספק ישראלי — לפי דרישות לקוחות Enterprise לגבי מיקום דאטה.
- כל התשתית כ-IaC (Terraform) — סביבה ניתנת לשחזור מלא מקוד.

## 2. CI/CD

Pipeline לכל PR (חוסם מיזוג):
1. Lint + Static Analysis (TypeScript strict, ESLint + כללי אבטחה, dependency-cruiser לגבולות מודולים)
2. בדיקות: Unit (פר-מודול) → Feature → **סוויטת Cross-Tenant** → Architecture tests (גבולות מודולים)
3. סריקת אבטחה: תלויות (pnpm audit), סודות, SAST (Semgrep)
4. נגישות: axe-core על מסכי מפתח; Lighthouse CI (תקציבי ביצועים)
5. Build + מיגרציות על DB נקי

Deploy: מיזוג ל-main → Staging אוטומטי → Production בקליק (עם אישור), Zero-Downtime (מיגרציות תואמות-לאחור בשני שלבים: Expand → Migrate → Contract), Rollback בפקודה אחת. Feature Flags מנתקים "פריסה" מ"הפעלה".

## 3. ניטור והתראות

| רובד | כלי | מה נמדד |
|------|-----|---------|
| APM | Sentry + APM (או מקבילה) | שגיאות, טרנזקציות איטיות, N+1 |
| תשתית | Prometheus/Grafana או ניטור ענן | CPU/RAM/דיסק/חיבורי DB |
| תורים | BullMQ Dashboard (Bull Board) + התראות | עומק תור, Jobs כושלים, זמן המתנה |
| עסקי-תפעולי | דשבורד פנימי | שיחות שנכשלו, Webhooks שנדחו, תבניות שנחסמו, Quality Rating של וואטסאפ, צריכת קרדיטים חריגה |
| Uptime | בדיקה חיצונית | API, דפי הצעה, Webhook endpoints |

- התראות מדורגות: Critical → טלפון/PagerDuty; Warning → ערוץ צוות. כל התראה עם Runbook מקושר.
- **ניטור פר-דייר**: תקלה של דייר בודד (מספר וואטסאפ נחסם, יומן מנותק) מוצגת גם לדייר עצמו במסך "בריאות החיבורים" — חוסך פניות תמיכה.

## 4. גיבויים ו-DR

- PostgreSQL: גיבוי מלא יומי + WAL רציף → שחזור לנקודת זמן (PITR). שמירה: 30 יום.
- S3: Versioning + רפליקציה בין-אזורית להקלטות ומסמכים.
- בדיקת שחזור **מתורגלת אחת לרבעון** (גיבוי שלא שוחזר = לא קיים).
- יעדים: RPO ≤ 15 דקות, RTO ≤ 4 שעות.
- Runbook אסון כתוב: מי מכריז, מה הסדר, איך מתקשרים ללקוחות.

## 5. תחזוקה שוטפת

- עדכוני תלויות: אוטומטיים (Dependabot) עם CI מלא; חלון תחזוקה חודשי לעדכוני תשתית.
- ניקויים מתוזמנים: Transients/טוקנים שפגו, הקלטות מעבר ל-Retention, ארכוב לידים ישנים, פרטישנים חדשים לטבלאות אירועים.
- Migrations דיסציפלינה: קדימה-בלבד, קטנות, הפיכות כשאפשר.
- תיעוד חי: כל מודול עם README (אחריות, אירועים, החלטות); Runbooks לכל תרחיש תפעולי; OpenAPI מתוחזק אוטומטית.

## 6. Onboarding דייר חדש (תהליך תפעולי-מוצרי)

אשף מובנה: פרטי משרד → הזמנת סוכנים → חיבור מספר וואטסאפ (תהליך מונחה מול Meta) → הפניית שיחות לסוכן הקולי (הנחיות פר-ספק סלולר) → ייבוא דאטה קיים (CSV/אקסל של נכסים וקונים עם מיפוי שדות חכם) → הגדרות שיתוף. יעד: משרד עובד תוך שעה, בלי איש תמיכה.

## 7. תמיכה ותפעול לקוחות

- Impersonation מבוקר: תמיכה יכולה "להיכנס כמו" משתמש רק באישורו, לזמן קצוב, עם Audit מלא.
- ייצוא דייר: כל הדאטה שלו בפורמט פתוח (CSV+JSON) בלחיצה — אמון + דרישה חוזית.
- סטטוס-פייג' ציבורי לתקלות רוחביות.
