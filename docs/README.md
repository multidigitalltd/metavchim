## עקרונות-על (חלים על כל מסמך)

1. **מהירות היא פיצ'ר** — יעד: תגובת API ‏P95 < 300ms, מסך ראשי < 2.5s (LCP), אינטראקציה מיידית.
2. **אבטחה כברירת מחדל** — כל קלט עובר ולידציה (Zod), כל פלט Escaping, כל פעולה בודקת הרשאה ושייכות דייר (Tenant), הכל מתועד ב-Audit Log. בידוד תלת-שכבתי: Scope → Policy → RLS.
3. **נגישות מובנית** — ת"י 5568 / WCAG 2.2 AA בכל רכיב, התאמות אישיות בפרופיל, כפתור נגישות בדפים הציבוריים, שערים אוטומטיים ב-CI.
4. **מודולריות אמיתית** — כל מודול עם גבול ברור, API פנימי ואירועים. אפשר להוסיף/להחליף מודול בלי לגעת באחרים.
5. **API-First** — כל יכולת קיימת קודם כ-API. הממשק, הוואטסאפ והסוכן האישי הם צרכנים של אותו API.
6. **אנטי-נעילה לספקים** — WhatsApp, טלפוניה, STT, LLM — כולם מאחורי שכבת הפשטה (Adapter).
7. **UX של "מה עכשיו"** — המערכת לא מציגה מידע, היא אומרת מה הפעולה הבאה (Next Best Action).
8. **מה שיוצא ללקוח — באישור בן אדם** — הצעה, הסכם, מייל: המערכת מנסחת, המתווך שולח.
9. **מינימום הקלדה** — קול ובחירה מתוך אפשרויות לפני טפסים; הכתבה בכל שדה.
10. **מקור אמת אחד** — לתוכן, למונחים, לטוקני עיצוב. שני עותקים נפרדים ביום שמתקנים אחד מהם.

## מה מחוץ להיקף התכנון הזה

- **האתר השיווקי** — נבנה בנפרד (WordPress). המערכת חושפת לו API ציבורי מצומצם (דפי נכס, מחירון) במידת הצורך.
- **Kanko** — מערכת חיצונית. נקודת המגע: קבלת לידים/ביקושים ממנה דרך אינטגרציה חתומה (מסמך 05 §4).
