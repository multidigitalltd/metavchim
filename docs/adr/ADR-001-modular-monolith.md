# ADR-001 · Modular Monolith ולא Microservices

**סטטוס:** מוצע · **תאריך:** 2026-07-27

## הקשר
מערכת רב-מודולרית (CRM, Matching, Voice, Messaging, Collaboration) שצריכה להיבנות מהר ע"י צוות קטן-בינוני, עם דרישה מפורשת להרחבה קלה בעתיד.

## החלטה
אפליקציה אחת פרוסה (Deploy יחיד + Workers), מחולקת פנימית למודולים עם גבולות קשיחים: לכל מודול API פנימי (Interfaces) ואירועי דומיין; אסורה גישה ישירה לטבלאות/מודלים של מודול אחר; הגבול נאכף בבדיקת ארכיטקטורה אוטומטית ב-CI.

## חלופות שנשקלו
- **Microservices מהיום הראשון** — נדחה: מכפיל תשתית, ניטור, דיבוג ותיאום; הורג מהירות בשלב שבו הצוות קטן והדרישות עוד זזות.
- **מונוליט "רגיל" בלי גבולות** — נדחה: הופך לבוץ תוך שנה; בלתי אפשרי לחלץ שירותים אחר כך.

## השלכות
- (+) מהירות פיתוח מקסימלית, טרנזקציות פשוטות, Deploy אחד.
- (+) מסלול צמיחה ברור: מודול שהופך לצוואר בקבוק (מועמדים: Voice, Matching) מחולץ לשירות — הגבולות והאירועים כבר קיימים.
- (−) דורש משמעת: הפרת גבולות "כי זה מהיר" חייבת להיחסם ב-Review + כלי.
