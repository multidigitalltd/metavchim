# ADR-003 · Multi-Tenancy: בסיס נתונים משותף + Row-Level Security

**סטטוס:** מוצע · **תאריך:** 2026-07-27

## הקשר
מאות-אלפי סוכנויות עתידיות; דליפת דאטה בין סוכנויות היא הסיכון הקיומי של המוצר; נדרשים גם פיצ'רים חוצי-דיירים מבוקרים (ביקושים אנונימיים).

## החלטה
בסיס נתונים אחד, `tenant_id` בכל טבלה עסקית, בידוד בשלוש שכבות:
1. Global Scope אפליקטיבי (TenantContext מה-Session בלבד, לעולם לא מהלקוח).
2. Policy הרשאות בכל Endpoint.
3. **PostgreSQL RLS** — `SET app.tenant_id` בכל חיבור; פוליסה חוסמת שורות זרות גם אם הקוד שגה.
טבלאות השיתוף (`shared_demands`) הן היחידות עם פוליסת קריאה חוצת-דיירים — והן נטולות PII בתכנון.

## חלופות שנשקלו
- **DB נפרד לכל דייר** — נדחה: תפעול ומיגרציות של אלפי DBs, יקר, והורג את פיצ'רי הרשת (התאמות בין סוכנויות). אופציה עתידית לדייר Enterprise בודד עם דרישה חוזית.
- **Schema נפרד לכל דייר** — נדחה: אותן בעיות מיגרציה, פחות יתרון.

## השלכות
- (+) תפעול פשוט, מיגרציה אחת, פיצ'רי רשת טבעיים, עלות נמוכה.
- (+) RLS נותן ביטחון גם מול באגים אפליקטיביים.
- (−) חובת משמעת אינדקסים (`tenant_id` ראשון) ובדיקות Cross-Tenant בכל CI.
- (−) "שכן רועש" — ממותן ב-Rate Limits פר-דייר ומכסות.
