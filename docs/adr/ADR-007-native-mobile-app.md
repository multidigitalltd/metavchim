# ADR-007 · אפליקציה נייטיב לנייד: Expo (React Native) על אותו API

**סטטוס:** מוצע · **תאריך:** 2026-09-17

## הקשר

[מסמך החזון](../01-vision-scope.md) §6 קבע: *„PWA תחילה; נייטיב רק אם יידרש (ההשקעה
ב-API-First מכינה את זה)”.* ה-PWA נבנתה, והיא עובדת — ובכל זאת נדרש נייטיב, משלוש סיבות
שאף אחת מהן אינה נפתרת בדפדפן:

1. **התראות Push אמינות.** Web Push ב-iOS פועל רק אחרי התקנה למסך הבית ומ-16.4, והמערכת
   ההפעלה מתייחסת אליו כאזרח סוג ב׳. ליד חדש שממתין מעל 24 שעות הוא ה-KPI המרכזי
   (חזון §7), והתראה שלא הגיעה היא ליד שאבד.
2. **הטלפון הוא כלי העבודה.** חיוג, וואטסאפ, הקלטת הודעה קולית לקליטת נכס, זיהוי שיחה
   נכנסת — כולם קרובים יותר בנייטיב, וחלקם (זיהוי שיחה) אינם קיימים בדפדפן כלל.
3. **המתווך בשטח.** אפליקציה מותקנת נפתחת ממסך הבית, זוכרת את ההתחברות, ועובדת נגד
   רשת סלולרית חלשה עם מטמון מקומי — בלי תלות בדפדפן שנפתח לדף ההתחברות.

## החלטה

**`apps/mobile` — Expo (React Native) ב-TypeScript, בתוך המונוריפו, צרכן של אותו API.**

- **Expo עם `expo-router`** — ניתוב לפי קבצים, כמו Next.js; אותו מודל מנטלי לצוות.
  בנייה בענן (EAS) בלי Xcode/Android Studio על כל מכונה; עדכוני JavaScript ללא חנות (OTA).
- **`@metavchim/shared` היא אותה חבילה** — סכמות Zod, תוויות, `leadWaiting`,
  `formatJerusalemDate`, `whatsappLink`. אין לוגיקה עסקית באפליקציה; מה שדרוש לה ואינו
  ב-shared עובר לשם (כך נוספו `PROPERTY_STATUS_LABELS` ו-`PROPERTY_TYPE_LABELS`).
- **Session בכותרת `Authorization: Bearer`** ולא בעוגייה. אותו Session בדיוק — אותה
  שורה במסד, אותה תפוגה, אותו „החיבורים הפתוחים שלי”; רק הנשא שונה
  (`apps/api/src/common/session-token.ts`). הטוקן נשמר ב-Keychain / Keystore
  (`expo-secure-store`), ולעולם לא במשתנה גלובלי או באחסון רגיל.
  ההתחברות מצהירה `client: "mobile"` ומקבלת את הטוקן בגוף; לדפדפן דבר לא השתנה.
- **CSRF אינו חל על הכותרת**: אתר זר אינו יכול לצרף `Authorization` בלי אישור CORS, ו-CORS
  נעול ל-`WEB_ORIGIN`. זו בדיוק ההנחה ש-`OriginGuard` כבר מתעד: בקשה בלי Origin אינה דפדפן.
- **RTL ועברית תמיד** — `I18nManager.forceRTL` + `supportsRTL` בבנייה. אין תמיכה בשפה
  אחרת, כמו ב-web.
- **מה שיוצא ללקוח — באישור בן אדם** (docs/README, עיקרון 8): חיוג ווואטסאפ נפתחים
  באפליקציות המכשיר; האפליקציה אינה שולחת דבר מעצמה.

### מה קיים

| מסך | מקור ב-API | מה עושים |
|-----|-----------|----------|
| התחברות · החלפת סיסמה | `POST /auth/login`, `/auth/login/verify`, `/auth/change-password` | אימייל+סיסמה, קוד אימייל כשמופעל; סיסמה זמנית חייבת להתחלף לפני הכול |
| היום | `/leads?open=true&order=oldest`, `/leads?requiresHuman=true`, `/appointments`, `/tasks`, `/notifications` | תור המענה מהשרת (הוותיק ראשון), הפגישות של היום, המשימות שלי (סימון „בוצע”) |
| לידים · ליד חדש · ליד | `/leads` (סינון במסד), `POST /leads`, `/leads/:id`, `PATCH :id/status`, `POST :id/notes` | קליטה מהירה; חיוג, וואטסאפ, סטטוס, ציר זמן והערה |
| קול | `/voice-intakes/transcribe`, `/agent/help`, `/agent/interpret`, `/agent/execute`, `/agent/conversation/turn` | הסוכן האישי: הקלטה → תמלול → הצעה לאישור → ביצוע, עם אותם כללים כמו ב-web |
| נכסים · נכס | `/properties`, `/properties/:id`, `:id/matches` | פרטים, מה חסר למוכנות, בעל הנכס, לקוחות מתאימים |
| לקוחות · לקוח | `/buyers`, `/buyers/:id`, `:id/matches` | דרישות, מימון, נכסים מתאימים |
| משימה חדשה | `POST /tasks` | מועד מהיר (`quickDueOptions`, שעון ישראל), עדיפות, קישור לישות |
| התראות · Push | `/notifications`, `PATCH :id/read`, `POST /notifications/push/device` | רשימה, ניווט לישות; **פוש נייטיב** דרך Expo Push, מאותה סריקה ואותו מטען מצונזר כמו הדפדפן |

- **Push נייטיב** ✅ — טבלת `device_push_tokens` (RLS), רישום אידמפוטנטי לפי טוקן, שליחה
  מהעובד באצוות של 100 עם `DeviceNotRegistered` → מחיקה; ההסרה לפני התנתקות; לחיצה
  על התראה מנווטת רק למסכים שקיימים (`routeForPushUrl`).
- **מטמון לא-מקוון** ✅ — `useQuery` עם `cacheKey` ב-AsyncStorage, במרחב של המשתמש,
  נמחק בהתנתקות; „אין חיבור — מוצג מה שנטען לפני X”.
- **שער טוקני העיצוב** ✅ — `verify:theme` משווה את `src/theme.ts` ל-`globals.css` ורץ ב-CI.
- **בנייה לחנויות** 🟡 — `eas.json` עם שלושה פרופילים וכתובת API לכל אחד; `eas init`
  ו-`eas credentials` נעשים פעם אחת בחשבון הארגון (ראו `apps/mobile/README.md`).
- **אייקונים** 🟡 — נוצרים מקוד בצבעי המערכת (`scripts/make-icons.mjs`); חבילת מיתוג מחליפה.

### מה **אינו** בשלב הזה

- ⬜ **עריכה** של נכס וקונה — הטפסים המלאים נשארים ב-web; מהנייד יוצרים ליד ומשימה,
  ומעדכנים דרך הסוכן („תעדכן את המחיר של…”).
- ⬜ **גופן Almoni** — ה-web טוען woff2, ו-RN דורש ttf/otf; עד להמרה, גופן המערכת.
- ⬜ שערי ניגודיות וטיפוגרפיה ייעודיים לנייד — הטוקנים נאכפים מול ה-CSS, שם השערים כבר רצים.

## חלופות שנשקלו

- **להישאר עם ה-PWA** — נדחה מהסיבות שבהקשר. ה-PWA נשארת; המתווך שאינו מתקין את
  האפליקציה ממשיך לעבוד בדפדפן, ואין תלות בחנויות לפיצ'ר חדש ב-web.
- **Capacitor (עטיפת ה-web הקיים)** — נדחה: מסכי ה-web בנויים לשולחן עבודה עם התאמה
  למובייל, לא להפך; העטיפה הייתה נותנת Push ואייקון, אבל לא את מהירות המגע, את
  הגלילה הנייטיבית ואת החיוג בלחיצה שהשטח מבקש. וכל תיקון היה תיקון בשני מקומות.
- **Flutter / Kotlin+Swift** — נדחה: שפה שנייה (או שלישית) בצוות TypeScript, ואובדן
  `@metavchim/shared` — בדיוק היתרון שלשמו נבנה המונוריפו (ADR-002).
- **React Native בלי Expo** — נדחה: ניהול Xcode/Gradle ידני על כל מכונה, בלי OTA ובלי
  EAS. Expo הוא ברירת המחדל של React Native היום, וה-CLI מאפשר יציאה ממנו בכל שלב.
- **טוקן JWT ל-mobile** — נדחה: זה היה סוג Session שני, עם תפוגה שאי אפשר לבטל מהשרת
  ובלי מקום ברשימת „החיבורים הפתוחים שלי”. הטוקן האטום הקיים כבר נותן ביטול מיידי,
  עידן סיסמה וחלון תמיכה — בחינם.

## השלכות

- (+) אפליקציה אחת נוספת, אפס שכפול לוגיקה: מה שמשתנה ב-shared משתנה בשני הלקוחות.
- (+) ה-API לא נפתח לשום דבר חדש — רק נשא נוסף לאותו Session, ותשובה נוספת להתחברות.
- (+) בידוד הדיירים והרשאות — זהים: ה-Guard, ה-RLS וה-`capabilities` שב-`/auth/me`
  משמשים את האפליקציה כמו את ה-web (`can()` באותו כלל: ברירת מחדל שלילית).
- (−) חנויות: פרסום, סקירה, חתימה. ניהול ב-EAS; לא חלק מה-CI של המאגר בשלב זה.
- (−) `pnpm-lock.yaml` גדל, ו-`pnpm install` ב-CI ובבניית Docker מתקין גם את תלויות
  הנייד. ה-Dockerfile מפרסם ב-`deploy --prod` רק את api ו-workers, ולכן התמונות אינן
  משתנות; אם זמן ההתקנה יכביד — `--filter` בשלב הבנייה הוא הפתרון.
- (−) טוקני העיצוב מועתקים ל-`src/theme.ts`. עותק שני של `globals.css` הוא בדיוק מה
  שהמסמכים מזהירים מפניו; הוא מסומן, קצר, ושער ההשוואה הוא בתוכנית.
